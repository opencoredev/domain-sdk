---
title: Poll until a domain is active
description: "Wait until a custom domain reaches the provider-reported active state with waitUntilActive: timeouts, intervals, AbortSignal cancellation, and Retry-After backoff."
---

```ts title="activate-domain.ts"
const controller = new AbortController();
const active = await domains.waitUntilActive("app.customer.com", {
  timeoutMs: 5 * 60_000,
  intervalMs: 5_000,
  signal: controller.signal,
  onStatus(domain) {
    console.log(domain.status);
  },
});
```

The first check runs immediately and checks never overlap. Delays start at five seconds and back off by 1.5x up to 30 seconds, the default timeout is five minutes, and a longer `Retry-After` from the provider wins. Permanent errors stop polling at once. After a check that doesn't return an active domain, it rejects with `TIMEOUT` once the deadline has passed (or early, when a `Retry-After` would run past it). It rejects with `ABORTED` when the signal fires, and with `VERIFICATION_FAILED` when `shouldStop` matches a domain that isn't active. By default that is the first check that sees `failed`, since waiting won't fix it; pass your own `shouldStop(domain)` to change the rule. It does not guarantee DNS propagation time.

If a domain never becomes active because its certificate stays pending, see [Troubleshoot custom domain SSL certificates](./troubleshoot-certificates.mdx).
