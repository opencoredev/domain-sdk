---
title: Error handling
description: "Handle DomainSdkError codes for auth, conflicts, rate limits, timeouts, and provider outages, with retryable flags, retryAfter, and redacted details."
---

```ts title="handle-domain-error.ts"
import { DomainSdkError } from "@opencoredev/domain-sdk";

try {
  await domains.add("app.customer.com");
} catch (error) {
  if (error instanceof DomainSdkError) {
    console.error(error.code, error.retryable, error.retryAfter);
  }
}
```

Errors normalize authentication, permission, conflict, not-found, rate-limit, provider availability, timeout, and cancellation states. Response details are bounded and recursively redact credential-shaped fields.

Every async client method returns a promise and reports failures by rejecting it, including invalid input, so `await` with `try`/`catch` or `.catch()` handles every case. Creating a client and the synchronous `SubdomainClient.toHostname()` / `fromHostname()` helpers throw synchronously.

| Code                    | When                                                                                                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `INVALID_CONFIGURATION` | A caller mistake in options: a missing provider, a `list()` limit outside 1 to 100, invalid `waitUntilActive()` polling or `retry` options, or creating a client in a browser. |
| `INVALID_HOSTNAME`      | A hostname, subdomain label, or DNS record name that cannot be used.                                                                                                           |
| `VERIFICATION_FAILED`   | `waitUntilActive()` stopped because `shouldStop` matched, by default when the domain reached `failed`. `details` holds the status and issues.                                  |
| `REQUEST_FAILED`        | The provider rejected the request or returned something the SDK cannot use: malformed JSON, a body over the size cap, or DNS records missing or mismatched after a write.      |
| `TIMEOUT`               | `waitUntilActive()` reached `timeoutMs` while the domain was still pending.                                                                                                    |

When a DNS write rolls back after an error, the rejected error preserves the underlying code (such as `REQUEST_FAILED`, `RATE_LIMITED`, or `PROVIDER_UNAVAILABLE`) and attaches `details.restored`, `details.replaced`, `details.externalChange` (when records outside the SDK's own writes changed concurrently), and `details.unexpected` (when unexpected or concurrent records remain; dropped locked records are reported in `details.collateralMissing`).
